1. PROJECT KYA HAI (OVERVIEW)
------------------------------------------------------------
Goal: Ek tool jo satellite map par khali plot select karne par
us plot ke andar MAXIMUM parking slots ka professional layout
automatically design kar de — aisles, entry/exit, accessible
stalls, EV stalls sab ke saath.

Pipeline (input se output tak):
  1. User satellite map par plot ke corners click karta hai
     (+ optional: obstacles jaise ped, pole, structure)
  2. Lat/Lng (WGS84) -> UTM metres conversion (pyproj se,
     UTM zone automatic; Indore = zone 43N, EPSG:32643)
  3. Usable area = boundary polygon MINUS obstacle polygons
  4. Optimizer har parking angle (0-90 deg) aur row offset try
     karke sabse zyada slots wala layout dhoondta hai
  5. Access lane reserve hoti hai, reachability check hota hai
  6. Result wapas lat/lng mein convert karke map par overlay

3. RESEARCH — YE KAAM PROFESSIONALLY KAUN KARTA HAI
------------------------------------------------------------
Log/roles jo real duniya mein parking layout design karte hain:
  - Traffic / Transportation Engineers (circulation, access)
  - Civil / Site Engineers (grading, drainage, paving)
  - Architects (building codes, sanction drawings)
  - Specialized Parking Consultants — US firms: Walker
    Consultants, Kimley-Horn, WGI. India mein architects +
    liaison consultants NBC/bye-laws ke saath.
  - Landscape architects (islands, shade trees, stormwater)

Unka standard WORKFLOW (important!):
  STEP 1: Site analysis — access road kahan hai, entry/exit
          kahan ban sakta hai (intersection se door)
  STEP 2: CIRCULATION FIRST — pehle aisle/lane network design
          hota hai, stalls baad mein. Rules:
            - Aisles plot ke LONG dimension ke parallel
            - Dead-end aisles AVOID karo — loop/flow-through
            - Har aisle ke dono taraf parking (double-loaded)
  STEP 3: Angle selection (turnover ke hisaab se):
            - High turnover (shops, clinic): 45-60 deg one-way
            - Low turnover (office, resident): 90 deg two-way
              (max density)
  STEP 4: Striping plan — accessible stalls entrance ke paas,
          EV stalls, islands, walkways, signage
  STEP 5: Code compliance check + sanction drawing

4. RESEARCH — STANDARDS & DIMENSIONS
------------------------------------------------------------
A) INDIA — NBC 2016 (National Building Code):
   - Minimum common car stall  : 2.5 m x 5.0 m
   - Individual/open stall     : 3.0 m x 6.0 m
   - Aisle: 90 deg parking -> 6.0 m
           angled parking -> 5.0-5.5 m
           parallel       -> 3.6 m
   - ECS (Equivalent Car Space) area norms:
           open parking     -> 23 m2 / car
           stilt parking    -> 28 m2 / car
           basement         -> 32 m2 / car
   - Basement: min 2 ramps opposite ends, slope max 1:8

B) BIS SP 73:2023 — shared parking stall 2.75 x 5.0 m
   (thoda comfortable; app mein preset hai)

C) INTERNATIONAL (US practice, feet -> metres):
   - Standard stall: 9 x 18 ft (2.7 x 5.5 m)
   - Aisle widths by angle:
       90 deg -> 24 ft (7.3 m)  two-way
       60 deg -> 18 ft (5.5 m)  ONE-WAY
       45 deg -> 13 ft (4.0 m)  ONE-WAY
       30 deg -> 11 ft (3.4 m)  ONE-WAY
   - 90 deg hi single config hai jo two-way support karti hai;
     angled parking one-way circulation maangti hai
   - EFFICIENCY BENCHMARK: surface lot 350-400 sq ft per car
     = ~32-37 m2/car (aisles included). Isse kam = efficient.
   - Structured garage: 300-350 sq ft (~28-32 m2) per car

D) ACCESSIBLE PARKING (India — Harmonised Guidelines 2021,
   MoHUA/CPWD, RPwD Rules; UK BS 8300 pattern similar):
   - Accessible bay: 2400 mm stall + 1200 mm transfer zone
     beside = 3600 mm total width (+1200 rear zone for boot)
   - Location: entrance ke SABSE PAAS, accessible route par
   - Signage: international accessibility symbol
   - Count: public buildings ~ min 2 ya ~4-5% of total
     (ADA/IBC: 1 per 25 spaces ratio bhi common reference)
   - Do accessible stalls EK shared transfer bay use kar
     sakte hain (pair pattern: [A][T][A]) — space efficient

E) EV CHARGING: modern codes 5-10% EV-ready + extra %
   EV-capable (conduit pre-installed)

F) LANDSCAPE ISLANDS: 1 island per 10-15 stalls (ya lot area
   ka min % landscaping) — heat island kam, stormwater, trees,
   light poles, wayfinding. End islands har row ke end par
   (min 5-6 ft wide).

G) OTHER PRO ELEMENTS (future ke liye):
   - Pedestrian walkways: 4-6 ft, striped/curbed, building tak
   - Fire lane: 20 ft (6 m) unobstructed
   - Entry/exit lanes: 10-12 ft each
   - End islands, wheel stops, drainage slope 1-5%

5. STAGE-2 APP — ARCHITECTURE
------------------------------------------------------------
Standalone local web app (Colab/Google API ki zaroorat nahi):

  optimizer.py  — core engine (Python: shapely, pyproj, numpy)
  app.py        — Flask server, POST /api/optimize
  static/index.html — Leaflet UI (free Esri satellite tiles,
                  Nominatim location search — NO API KEY)

  Run: python app.py  ->  http://localhost:5000

Algorithm (engine):
  1. WGS84 -> auto UTM zone -> shapely polygons
  2. usable = boundary - union(obstacles); MultiPolygon ho to
     largest piece (+warning)
  3. Orientation: longest edge ke PARALLEL aur PERPENDICULAR
     dono rotations try hoti hain (squarish plots doosri
     taraf better pack hote hain)
  4. Two-stage angle sweep: coarse 5-deg step (11 offsets)
     -> fine 1-deg around best (15 offsets) — fast + accurate
  5. CIRCULATION FIRST: access lane (6 m car / 3 m bike)
     pehle RESERVE hoti hai, phir bache area par best 3
     candidate angles 31 offsets se re-optimize — isliye koi
     slot spine se conflict karke waste nahi hota
  6. Reachability: sirf wo slots count hote hain jo access-
     lane-connected aisle ko touch karte hain
  7. Striping plan (classification):
       - islands: har Nth stall -> landscape island
       - accessible: entry ke nearest pairs [A][T][A] shared
         transfer bay ke saath
       - EV: uske baad ke nearest stalls
  8. Result -> rotate back -> UTM -> lat/lng -> JSON

v3.1 FIX — COURTYARD MODE (19 Aug 2026, user bug report):
  Problem: chhote plot (house compound ~256 m2) par bay-layout
  logic fail — 6m access lane + aisle grid fit nahi hota tha,
  sirf 2 ajeeb stalls aa rahe the. User ne screenshot bheja.
  Root cause: engine sirf "bay + aisle" pattern jaanta tha,
  jo bade lots ke liye hai. Chhote plots real duniya mein
  COURTYARD style hote hain: stalls boundary ke along, saamne
  shared maneuvering court, gate se direct entry, koi aisle
  grid nahi.
  Fix: perimeter_layout() — har edge par 90 deg / parallel
  stalls greedy place hote hain, har stall ke saamne apron
  (maneuvering) polygon jo plot ke andar hona chahiye aur
  kisi stall se overlap nahi; reachability = stall gate wale
  free court component ko touch kare. Bay vs courtyard dono
  compute hote hain, zyada stalls wala jeet-ta hai (tie ->
  courtyard). Stats mein "layout_mode" aata hai.
  FP BUG bhi mila: boundary line par exact rakhe stalls
  floating-point se 1e-9 m bahar nikal ke covers() fail kar
  rahe the — fix: 5 cm inset (real striping paint gap) +
  area-based overlap checks (touch != overlap).
  Results: small compound 2 -> 8 stalls; narrow strip 8x22m
  -> 3 stalls + transfer bay; big plot unchanged (43, bay).
